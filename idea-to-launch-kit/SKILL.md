# AI 产品从想法到上线

以产品经理能亲自复核的结果为交付单位。先确定用户这次要做到需求、可运行的本地产品，还是小范围上线。已有 PRD、方案、设计稿和项目进度优先复用。

## 开工与续做

1. 查看目标工作区的规则和现有文件。如果已有 `kit.sh` 和 `projects/`，直接复用，读取相应产品的 `docs/项目状态.md` 和流程状态。若是新项目，把 [随包启动工程](assets/starter/) 完整复制到用户工作区的独立子目录，包含隐藏文件，保留脚本执行权限。在新工具包根目录执行 `git init`，供自检识别将进入仓库的文件。避免覆盖现有代码或配置，也不要在 Skill 安装目录开发。
2. 在工具包根目录读取 [原项目规则卡](assets/starter/AGENTS.md)。以当前会话与目标工作区的授权为准。产品文档与证据放在 `projects/<产品名>/docs/`。如果有 PRD 和配套方案，一并纳入技术适配，说明采纳和调整的组件。
3. 从工具包根目录执行 `bash kit.sh 任务 "<产品名>"`。按输出读取对应章节并工作。优先检查环境与前置产物，按用户要求的交付层级推进。

## 阶段与资料

| 阶段 | 交付与参考 |
| --- | --- |
| 0 PRD 体检 | 用 [PRD 模板](assets/starter/docs/PRD模板.md) 补用户、主流程、范围和验收标准。最多集中问五个关键问题，附推荐答案。 |
| 1 技术适配 | 根据规则卡及 `docs/手册/` 下的技术手册，交付技术适配声明，覆盖架构、模型、数据、成本、验收与上线边界。 |
| 2 后端 MVP | 先跑通核心链路，再按技术手册做真实模型冒烟、重启恢复与产品效果验收。模拟数据可用于开发，单独标记证据。 |
| 3 正式前端 | 按前端技术栈手册与用户参考做界面，验证主流程、错误和空态，以及桌面和手机交互。 |
| 4 上线 | 用户要求部署时读取部署手册及对应参考代码。默认参考腾讯云开发，实际执行前核实平台流程、计费与范围。需要用户授权、实名或创建付费资源时，明确指出具体步骤与影响。 |
| 5 收尾 | 整理复跑和接手说明，核对线上地址、资源归属与凭据依赖，记录已验收和待处理事项。 |

详细人工操作见 [原项目操作手册](assets/starter/开始看这里.md)。部署参考脚本涉及云资源或凭据，按实际目标审查参数和副作用后才执行。密钥仅经本地安全配置或平台密钥管理进入服务，避免进入前端、仓库、对话和证据包。部署时验证用户数据隔离与错误信息脱敏。

## 自检、验收与交接

- 按规则卡生成阶段证据包。保留原始自检输出、可复核的路径或操作步骤，以及适用的截图、冒烟记录和是否表。任何环境阻塞或未验证项按实记录。
- 执行 `bash kit.sh 自检 "<产品名>"`。自检通过且用户明确验收当前阶段后，执行 `bash kit.sh 通过 "<产品名>"`。有分支时按脚本提示和用户范围选择下一阶段。不要手改脚本管理的流程状态。
- 在项目状态文档写清当前阶段、已作决定和下一步。用户只要求当前阶段时，交付该阶段证据并停在对应验收点。
